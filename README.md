# 使用说明

## 安装与启动

1. 下载发布页中的 `.exe` 安装包，完成安装后从开始菜单启动。
2. 点击“导入诊断包”或将支持的 TGZ 文件拖进窗口；也可以选择下载目录，再点击“开启监控”。
3. 分析完成后点击“打开 HTML”。报告位于诊断包旁的同名目录中，文件名为 `report.html`，可离线打开。
4. 点击“关键词与报告规则”维护提取条件、系统字段、时间线及展示样式。

关闭窗口后程序进入托盘。从托盘选择“退出”才会停止程序。分析列表仅在本次运行中保留，不保存历史诊断数据库。

诊断包成功或失败时发送 Windows 系统通知：点击成功通知直接打开对应 HTML 报告，点击失败通知显示并定位任务。取消和等待文件稳定重试不通知。通知遵循 Windows 的通知及免打扰设置；退出程序时清除本次通知。

点击主窗口标题栏中的齿轮打开设置，可启用“开机自启”和“开机自动最小化到托盘”，点击“保存”后生效。“取消”不修改设置。自启仅作用于当前 Windows 用户；自动最小化只在开机启动时生效，手动启动仍显示窗口。托盘运行时沿用已保存的目录监控开关。

## 文件位置

- 默认按当前用户安装到 `%LOCALAPPDATA%\Programs` 下的应用目录，无需管理员权限。
- 规则位于安装目录中的 `assets\default-rules.json`，该目录需要可写。
- 软件设置和规则同步记录位于 `%LOCALAPPDATA%` 下按应用名划分的目录；同步密码保存在系统凭据管理器。
- 解压日志及 HTML 报告位于原诊断包旁的同名目录，不放入安装目录。
- 升级不会覆盖已有规则；卸载会保留规则和用户设置。本次规则格式使用 version 3，不读取或迁移旧版规则。

## 目录监控与任务

- 只监控所选目录的直接文件，开启或恢复监控时忽略已有诊断包。
- 新下载、复制或移动进来的 TGZ 会排队分析，同名覆盖后可重新分析。
- 文件连续 10 秒稳定后进行完整性校验。不完整或损坏的文件显示原因，确认删除时仅移除压缩包，保留已有报告目录。
- 多任务逐个执行，可按任务状态取消或重试。取消或失败会保留已生成文件，旧报告不计为本次成功。
- 解压时覆盖同名文件并保留其他文件；本次分析不会读取上次诊断包残留的日志。
- “清理已完成”仅处理本次成功分析且直接位于当前监控目录的诊断包及同名输出目录，操作前会确认具体路径。存在活动任务时不可用。
- 文件发生变化或清理失败时会保留记录和原因；失败、取消及未记录的历史结果不会批量清理。

## 规则编辑与同步

关键词支持任意或全部匹配、排除词、大小写和正则表达式，前后文行数可分别配置。关键词命中是线索，不是故障结论。

先点击“新增日志文件”维护中文名称、归档内路径、匹配方式和归档类型，再在该日志文件下添加规则。来源支持精确相对路径、文件名或相对路径前缀、路径包含。路径无需包含诊断包最外层目录。包内 gzip 轮转日志可以参与分析。ZIP 选项仅为后续支持预留，当前保存或分析 ZIP 会提示暂不支持。

关键词和时间线规则可多选已维护的日志文件，系统信息规则选择一个日志文件。列表和规则选择只显示中文名称与文件名，完整路径只在日志文件配置表单中显示。名称和路径只在日志文件目录中维护；改名不会改变规则身份。引用中的日志文件不能删除，需先调整或删除引用它的规则。

拖动左侧日志文件栏的分隔条可调整宽度（180～360），点击“保存全部”后记住宽度；窄窗口自动使用日志文件下拉选择。

点击规则展开，使用“编辑”打开配置抽屉。新增规则按来源、提取条件和展示设置逐步配置。支持排序、复制、移动、导入、导出及样例预览。搜索期间禁用排序。

弹窗中的“完成”只将修改加入草稿，“保存全部”才写入规则文件。取消编辑会撤回本次草稿；保存失败时可保留草稿重试。“还原默认规则”也只更新草稿，保存后才生效。

导入先预览，再选择冲突处理，默认保留现有配置。导入和导出均使用 version 3 JSON，不兼容旧版 `files / keywords` 或 version 2。导出选中规则时会携带它引用的日志文件目录。

规则 JSON 顶层的 `log_files` 保存 `id`、`name`、`path`、`mode`、`container`。`path` 是唯一的归档内路径配置；不另存相同含义的 `entry_path`。关键词和时间线使用 `source_file_ids` 数组保留多文件匹配，系统信息使用 `source_file_id`。规则不再重复保存路径；`group` 保留内部排序和关联含义，报告显示名读取日志目录。

网络规则同步可配置单个服务器，并提供上传、下载和双向同步。测试连接不会保存配置。下载或接受远端版本会直接保存并刷新当前规则；写入失败会显示原因并保留旧规则。

## 报告阅读

- 关键词按日志文件中文名分组；多文件规则显示在各自的日志目录下。默认隐藏无命中规则，勾选“显示未命中规则”可查看。
- 点击关键词规则可查看聚合日志，同文件重叠上下文去重，保留行号和高亮；日志按配置行数分批显示。
- 每条关键词规则最多保留 500 处命中及相应上下文，总命中数来自完整扫描。报告会标明省略数量；搜索、复制和打印仅覆盖报告内嵌证据。
- 系统信息支持卡片、表格、容量转换、存储池和硬盘详情。SMART 数据按原始磁盘位置关联，未知状态保留原值，不推断健康结论。
- 时间线缺少年份或时区时不会自动补全，仅合并完整且口径一致的相同事件时间。已知时区可在规则中明确设置。
- 更新规则后，已有报告需要重新生成才能体现变化。

## 开发验证

```powershell
cargo test --locked
cargo build --release --locked
node scripts/test_storage_health.cjs
python scripts/validate_catalog.py
python scripts/validate_report.py --output target/catalog-validation/report.json
```

程序产物位于 `target/release/`，安装脚本位于 `installer/`。性能测量只使用隔离的诊断包副本，记录耗时，不设置固定耗时门槛。

版本标签触发自动测试、程序构建、安装包构建及正式发布。标签须与包版本一致，中文发布说明位于 `docs/releases/`。

## 使用边界

不包含 ZIP 诊断包支持、自动故障结论、诊断包云端上传、自动更新、历史数据库或自动文件清理。报告样式通过预设配置调整，不执行自定义 HTML、CSS 或脚本。样本和诊断数据不随安装包分发。
